# AI 出题流式编辑器设计说明

## 背景

当前 `AI 出题` 页面采用自上而下的后台表单布局：上方是生成配置，中段是草稿审核，下方是最近题目列表，底部附带运行状态与题篮能力。虽然功能完整，但页面观感偏“管理后台”，缺少 AI 创作工作台应有的节奏感，也无法把“题目是如何一步步生成出来的”直观呈现给用户。

本设计将 `AI 出题` 重构为一个强调连续产出、逐段可编辑、过程可感知的新页面。目标不是暴露模型内部推理，而是透明展示每一道题的产物如何从空白变成完整题干、答案与解析。

## 目标

- 把 `AI 出题` 从表单页升级为带强视觉识别的创作式工作台。
- 让用户在生成过程中实时看到每道题的题干、答案、解析逐步产出。
- 支持生成中即编辑，避免“等整批生成完再统一返工”。
- 维持现有入库、丢弃、批量管理等能力，但降低它们对主创作流程的干扰。
- 保持与现有后端任务流、草稿预览、题库入库机制兼容。

## 非目标

- 不展示模型隐式推理链或内部思考。
- 不重写 `Question Library` 或 `RunPanel` 的全部底层逻辑。
- 不在第一版引入复杂的多会话协作或版本历史系统。

## 用户体验定位

页面定位为 `Editorial AI Studio`，不是传统管理后台。

视觉风格应明显跳出当前灰白线性后台语言，转向更强设计感的创作界面：

- 暖白纸面感背景，叠加细颗粒或浅网格肌理。
- 深石墨文本色，钴蓝色高亮，少量朱砂红/琥珀色作为动作与状态提示。
- 宽画布、强层次、明确节奏，让页面打开后就像进入“出题引擎”而不是“配置中心”。
- 动效围绕“产物出现”展开，弱化通用 hover 小动效。

## 核心设计决策

### 1. 页面形态

采用 `编辑器工作台` 方案，而不是继续沿用表单页。

页面结构为：

- 顶部 `Mission Bar`
- 中央 `Generation Stream`
- 右侧 `Context Rail`
- 底部 `Confirmed Shelf`

这是一种“中间画布优先”的布局。用户的注意力应该始终停留在正在生成的题目卡片上，而不是停留在参数区或系统工具栏上。

### 2. 透明性定义

“过程透明”指向产物层透明，而不是推理层透明。

用户可以看到：

- 当前正在生成第几题
- 每道题已经完成到哪一步
- 哪一段内容刚刚生成完成
- 哪一段是用户手动修改过的
- 哪一道题卡住、失败、重试或已确认

用户不需要看到：

- 模型的隐式 Chain-of-Thought
- 过度技术化的请求/响应细节

### 3. 工作流

采用 `连续产出编辑器` 模式，而不是“整批生成后再统一审核”。

理想流程：

1. 用户输入自然语言任务。
2. 系统创建生成会话并预置若干题目占位卡。
3. 每张卡按 `题干 -> 答案 -> 解析 -> 审核` 顺序推进。
4. 用户可在任意时点直接编辑某段内容。
5. 已确认题目进入底部收纳区。
6. 未确认题目继续留在主流中等待调整。

## 页面信息架构

### Mission Bar

顶部区域是全页最强视觉焦点。

职责：

- 接收自然语言出题任务
- 承载少量核心参数
- 折叠高级配置，避免一开始就是密集表单

内容建议：

- 一条大尺寸 prompt 输入区
- 核心 chips：学科、题量、难度、题型
- `引用自学资料` 开关
- `开始生成` 主按钮
- `高级控制` 入口，展开后再展示细节配置

默认文案示例：

> 为高一数学生成 5 道函数单调性中等难度题，包含答案和解析

### Generation Stream

中央区域是页面主舞台。

表现形式不是简单列表，而是一条具有时间感的生成流。用户启动任务后，中央画布中出现预置的题目卡片：

- `题目 01`
- `题目 02`
- `题目 03`

每张卡拥有明确的阶段状态：

- `题干生成中`
- `题干已完成`
- `答案补全中`
- `答案已完成`
- `解析生成中`
- `待确认`
- `已确认`
- `生成失败`

每张卡内部拆成三个可见的产物区块：

- `题干`
- `答案`
- `解析`

每个区块都要支持：

- 可编辑
- 显示状态
- 显示更新时间
- 局部重生成
- 锁定本段

### Context Rail

右侧栏用于承载辅助上下文，不抢中央画布。

建议内容：

- 本次任务摘要
- 当前任务进度
- 参考了哪些学习档案/知识点
- 当前运行状态（进行中、已暂停、失败）
- 快速跳转到某一道题
- 全局控制：暂停、继续、重跑、结束入库

这一区域更像控制面板和导航索引，而不是信息主舞台。

### Confirmed Shelf

底部收纳已确认题目。

目的：

- 避免主画布在长任务中持续膨胀
- 清楚区分“仍在加工”与“已通过审核”
- 帮助用户建立完成感

表现形式可以是横向题目条带，也可以是折叠抽屉。

## 关键交互

### 启动生成

点击开始后，不再仅仅显示一个独立 `RunPanel`。系统应立即让中央画布发生变化：

- 生成 session
- 渲染占位题卡
- 显示当前任务节奏

用户应在 1 秒内看到页面进入工作状态。

### 流式产出

题目卡片应按阶段渐进式展开：

- 先显示题干骨架
- 题干完成后开放答案区
- 答案完成后开放解析区
- 全部完成后进入待审核态

动效建议：

- 区块淡入
- 状态标签切换
- 卡片从“草稿态”过渡到“稳定态”

### 生成中编辑

用户可以在任务执行期间编辑已有产物，不必等待整批完成。

编辑后可选交互：

- 标记 `已手动改写`
- 锁定该区块，后续生成不再覆盖
- 对单区块执行 `重新生成`

### 单题级恢复

单题失败不应打断整批任务。

失败卡片提供：

- `重试本题`
- `仅重生成解析`
- `跳过此题`

### 确认入库

题目确认后应从主流弱化，进入底部 `Confirmed Shelf`。

入库行为可采用两段式：

- `确认`：进入已确认队列
- `全部确认后入库` 或 `即时入库`

第一版建议保留现有 preview/commit 语义，但从 UI 上包装成更自然的确认动作。

## 视觉语言

### 色彩

- 基础背景：暖白、纸感浅米灰
- 主文本：深石墨
- 主强调：钴蓝
- 信息高亮：青蓝
- 警示：琥珀
- 失败：朱砂红

### 材质

- 顶部可使用轻微径向光晕
- 主画布可叠加浅颗粒、浅网格或极弱的横线纸张质感
- 卡片采用高圆角与轻阴影，层级要明显但不过度浮夸

### 字体

建议中文保持高可读性，无需过度装饰。

推荐组合：

- 中文：`Noto Sans SC`
- 英文/数字标签：`Space Grotesk` 或 `IBM Plex Sans`

数字编号、状态 chips、时间标签适合使用更有节奏感的西文字体，以强化“编辑器”气质。

## 状态设计

页面至少覆盖以下关键视觉状态：

1. 空状态
2. 已输入任务但未开始
3. 生成中
4. 单题编辑中
5. 单题失败
6. 全部完成待确认
7. 已确认题目沉到底部
8. 会话中断/重连

## 与现有实现的映射

现有能力中可复用部分：

- 学科数据：`useSubjects`
- 题库筛选与选中：`useQuestionLibrary`
- 任务执行与草稿预览：`useQuestionLibraryTasks`
- 草稿入库/丢弃接口：`commitQuestionLibraryPreview` / `discardQuestionLibraryPreview`

需要重构的部分：

- 页面结构从“滚动页面”改为“编辑器式工作台”
- 草稿数据从“统一预览块”转为“按题卡分段展示”
- `RunPanel` 从底部附属视图转为右侧上下文的一部分或其数据来源
- 批量删除从页面主动作降级为次级管理动作

## 前端组件建议

- `AiGenerateStudioPage`
- `MissionComposer`
- `AdvancedControlsSheet`
- `GenerationStream`
- `QuestionDraftCard`
- `ArtifactSection`
- `ContextRail`
- `ConfirmedShelf`

## 状态模型建议

建议把前端状态拆成三层：

- `session`：本次任务级状态
- `drafts`：每道题的流式产物状态
- `confirmedIds`：已确认题目集合

如后端可提供更细粒度事件，理想事件包括：

- `question_started`
- `stem_ready`
- `answer_ready`
- `analysis_ready`
- `question_failed`
- `question_confirmed`

如果暂时没有细粒度事件，第一版可通过前端派生阶段态模拟“逐段出现”体验。

## 风险与约束

- 当前后端任务流可能更偏整批返回，需要评估是否能提供更细粒度阶段事件。
- 现有草稿结构以整批 preview 为中心，改为题卡流后需要注意兼容。
- 页面视觉升级较大，必须确保移动端与窄屏下仍可使用。
- 强设计感不能以牺牲输入效率为代价。

## 验收标准

- 用户首次进入页面即可理解“输入任务 -> 逐题生成 -> 逐题确认”的流程。
- 生成中页面始终有明确节奏，不出现“只转圈、不知道发生什么”的状态。
- 用户能对单题或单段内容进行修改与重试。
- 页面整体感受像 AI 创作工作台，而不是传统后台表单。
- 与现有题库入库链路保持兼容。
